Economia portale

Valute (cosa compare nel pagamento) e listino MySQL + routing oggetto/toon. Layout a tutta larghezza per tabelle leggibili. Le sole valute che addebitano oggi in myst sono MXP e Rune; le altre sono solo UI finche' non c'e' codice di addebito dedicato.

Valute di pagamento

«Visibile ai giocatori» controlla solo la UI. pays_listino e' consentito solo per i tender dichiarati da myst (/internal/edit-capabilities). Ogni valuta pagabile si miscela solo con le rune (bilanciamento dedicato per valuta).

Listino e routing oggetto/toon

Prezzi in MySQL + dove va ogni edit. Nuove voci affect usano un codice APPLY_* gia' gestito da myst: senza quel codice in C++ non c'e' effetto in gioco. Dopo Salva: reload myst automatico.

      Nessun oggetto selezionato.

      I pezzi Lab vengono personalizzati sul target (EDIT + istanza) cosi' compaiono in inventario anche se prototipo trash/other/RARO.

      Categorie oggetto nel portale

      Spunta = tipo visibile e editabile al primo edit. Senza spunta = nascosto (pezzi in DB edits / EDIT+ED* restano, anche RARO). TAN/HAS-GEMS/simbolo sempre esclusi. Edit da indossato consentito (PG offline).

      Consultazione object_instance

      Tabella MySQL degli oggetti già personalizzati salvati nel mondo (id istanza, vnum base, owner, descrizione). Quasi sempre sono indossati: per lavorarci cerca l'owner, impostalo come personaggio target sopra, poi apri l'oggetto dall'inventario — i pezzi sono editabili anche indossati (primo edit e ri-edit), purché il PG sia offline e il pezzo rispetti categorie/esclusioni. Cerca l'owner, impostalo come personaggio target, poi apri l'oggetto dall'inventario.

      Con Lab attivo: usa «Clona sul target» per copiare un'istanza EDIT sull'inventario del personaggio target selezionato.
