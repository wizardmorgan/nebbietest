Accesso account

Usa l'email e la password dell'account (tabella user), non la password del singolo personaggio.

Seleziona personaggio

Il personaggio di sessione determina i permessi (player / limited / staff).

Personaggio target

Il personaggio di sessione (in alto) serve solo per i permessi staff. Qui scegli su chi lavori: inventario, edit oggetti e pagamento.

Edit sul personaggio target

Pool (hit, mana, move, regen) e resistenze sul PG selezionato sopra — non sul login staff.

Inventario

    Visibilità tipi: impostata dallo staff in basso (categorie). Oggetti già editati del PG restano ri-editabili.

    Nessun oggetto in inventario MySQL per questo PG.

    Oggetto selezionato

    Seleziona un oggetto editabile dall'inventario del personaggio target.

    Pagamento edit

    Il costo viene scalato dal personaggio target (MXP / Runes), non dal login staff.

    Staff — configurazione sistema

    Categorie oggetto nel portale

    Spunta = quel tipo ITEM compare nell'inventario del personaggio target ed è editabile. Senza spunta = nascosto. Gli oggetti con flag EDIT del PG restano sempre ri-editabili.

    Routing edit: oggetto vs personaggio avanzato — JSON di sistema

    Questo JSON (edit_system.json) decide dove va ogni tipo di edit: target: "object" = affect sull'equipaggiamento; target: "character" = valore sul PG (pool hit/mana/move o resistenza in tabella). Non è l'inventario: è la regola di sistema. Di solito lo lasci così e usi le checkbox categorie sopra.

    Consultazione object_instance

    Tabella MySQL degli oggetti già personalizzati salvati nel mondo (id istanza, vnum base, owner, descrizione). Quasi sempre sono indossati: per lavorarci cerca l'owner, impostalo come personaggio target sopra, poi apri l'oggetto dall'inventario — i pezzi già editati (flag EDIT) sono ri-editabili anche indossati. Il primo edit su un pezzo nuovo richiede ancora inventario (non wear).
